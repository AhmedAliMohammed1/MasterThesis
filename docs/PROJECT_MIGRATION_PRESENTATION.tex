\begin{frame}[t]{Current stage: working pipeline, unresolved 3D accuracy}
\large
We can deploy the migrated detector, convert Ouster clouds and display its output.
\medskip
\begin{block}{Current development choice}
Use reflectivity divided by 255 for this model and these recordings.
Neither tested channel is accepted as accurate 3D detection.
\end{block}
\normalsize
\begin{itemize}
\item Migration: Ubuntu 24.04, ROS Jazzy and TensorRT 10.
\item Integration: original bags, explicit adapter, monitoring and RViz.
\item Latest evidence: 1,120 measured GPU inferences and 119 Python tests.
\item Main research task: explain vertical error and input/capacity mismatch.
\end{itemize}
\small Source: \code{config/ouster_channel_decision.json}; reviewed 8 November 2026.
\end{frame}

\begin{frame}[t]{Why the migration was necessary}
\begin{center}
\begin{tikzpicture}[font=\small,>=Stealth,
 stage/.style={draw=accent,align=center,text width=5cm,minimum height=1.5cm}]
\node[stage] (old) at (0,0) {Ubuntu 20.04\\ROS Foxy / TensorRT 8};
\node[stage] (work) at (6.6,0) {Update message and tensor APIs\\Validate sizes; reuse GPU resources};
\node[stage] (new) at (13.2,0) {Ubuntu 24.04\\ROS Jazzy / TensorRT 10};
\draw[->,accent,thick] (old)--(work);\draw[->,accent,thick] (work)--(new);
\end{tikzpicture}
\end{center}
\medskip
\begin{itemize}
\item Preserve the pretrained ONNX; this work does not retrain the network.
\item Separate geometry tests, ROS message handling and GPU inference.
\item Check input layouts, output counts and GPU failures explicitly.
\item Reuse the engine, context, CUDA stream and buffers between scans.
\end{itemize}
\medskip
Successful migration establishes software compatibility. Accuracy requires a separate evaluation.
\end{frame}

\medskip

\begin{frame}[t]{Deployment and engine reuse are separate caches}
\begin{columns}[T,onlytextwidth]
\begin{column}{.48\textwidth}
\textbf{Image preparation}
\begin{itemize}
\item Host driver and Docker GPU access must already work.
\item Deployment builds local source by default.
\item Matching runtime checksum skips Docker build.
\item Source builds reuse dependency/model layers.
\item Base pulls are explicit; first builds can download dependencies.
\end{itemize}
\end{column}
\begin{column}{.48\textwidth}
\textbf{Container startup}
\begin{itemize}
\item Check model checksum and selected GPU.
\item Reuse a matching persistent engine.
\item Otherwise build from ONNX with trtexec.
\item Load once; reuse for each cloud.
\item Ctrl+C stops owned processes and preserves the cache.
\end{itemize}
\end{column}
\end{columns}
\medskip\small
\code{PP_BUILD_ONLY=1} is optional: prepare the image and exit.
Without it, \code{deploy.sh} starts the detector alone.
\end{frame}

\begin{frame}[t,fragile]{Run the original Ouster bag in three terminals}
\small
Prepare the image first; bags must already be downloaded:
\begin{verbatim}
sudo env PP_BUILD_ONLY=1 bash tools/deploy.sh
# Terminal 1: adapter and detector
sudo bash tools/start_ouster.sh bag
# Terminal 2: read-only original recording
sudo bash tools/start_ouster_bag.sh
# Terminal 3: desktop viewer, without sudo
ROS_DOMAIN_ID=99 RMW_IMPLEMENTATION=rmw_fastrtps_cpp \
  RVIZ_CONFIG="$PWD/rviz/ouster.rviz" \
  bash tools/visualize.sh -f lidar/os_lidar
\end{verbatim}
\medskip
Bag profile: Fast DDS, domain 99, raw \code{/sensing/lidar/points}.
Adapter output \code{/point_cloud}; detections \code{/bbox}.
\par\smallskip
Live mode has different defaults: Zenoh, domain 0, \code{/ouster1/points}.
Match the driver and router. Allow up to eight seconds after one Ctrl+C.
\end{frame}

\begin{frame}[t]{What the supplied ground truth can establish}
\begin{itemize}
\item Dur360: 16 published train scans and 16 test scans, frozen before inference.
\item Published indices are disjoint within one collection; independent-drive
separation is not established.
\item Original paper describes model-assisted labels with experienced human review.
The Extended card does not separately detail its labeling process.
\item Evaluation test region contains 60 vehicles and six pedestrians. Eleven
original test labels lie outside the declared region; no cyclists occur.
\item Class-aware, one-to-one matching: Vehicle IoU at least 0.7;
Pedestrian IoU at least 0.5, in BEV and 3D separately.
\end{itemize}
\small
The 1,120 runs contain repeated scans, not 1,120 independent scenes.
MOSEP supplies weather data but no object-detection ground truth.
This is a diagnostic subset, not an official benchmark score.
\end{frame}

\begin{frame}[t]{Capacity affects repeatability; the height problem remains}
\begin{itemize}
\item Engine input capacity: 204,800 points. Original Dur360 scans: 262,144 points.
Identical region/invalid-return preparation is necessary for this study.
\item Twenty of 32 primary scans exceed 10,000 occupied pillars; every scan
has pillars containing more than 32 points.
\item Separate control keeps first encountered pillars and points, preserving
order. It is a sensitivity test, not a reproduction of CUDA scheduling.
\item The control removes empty/nonempty repeat changes in this sample.
It retains four versus zero vehicle BEV matches and zero qualifying 3D matches.
\end{itemize}
\medskip
\textbf{Interpretation:} investigate bounded capacity and the model/input contract.
No production preprocessing fix or arbitrary z offset was installed.
\par\smallskip\small
Earlier KITTI/TRT8 tests also show poor 3D accuracy and elevated car centers;
this supports a shared investigation, not a universal correction.
\end{frame}

\begin{frame}[t]{Proposal: one baseline, then a fresh acceptance study}
\begin{enumerate}
\item Keep reflectivity/255 as the experimental baseline; record schema, model,
engine, divisor and operating threshold.
\item Declare and test valid-return and pillar-capacity policies.
\item Trace sensor origin, training coordinates, anchors and decoder semantics.
Do not fit a z offset to the inspected test labels.
\item If necessary, choose or fine-tune an Ouster-compatible model.
\item Freeze the corrected configuration and evaluate new, recording-disjoint
annotated scenes, including pedestrians, cyclists and weather variation.
\end{enumerate}
\medskip\small
Report per-class 3D/BEV precision, recall, AP, localization error, failures and latency.
An 80\% precision/recall pilot gate is a proposal requiring agreement, not an accepted standard.
\par\smallskip
Thesis starting points: \code{docs/THESIS_DRAFT.tex} and
\code{docs/OUSTER_CHANNEL_DECISION.md}. The current result is a supported development
choice with a documented accuracy failure.
\end{frame}
